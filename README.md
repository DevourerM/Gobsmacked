# Gobsmacked

一个完全本地、以时间为索引的个人记录系统。它将文字、图片、录音、标签、地点、日期标注和纪念星位事件收纳为版本化的 `.gob` 记录，并提供日 / 年编辑、月历与内层时间轴查阅。

## 已有能力

- 首次身份建立后，启动密钥与历史密钥分别设置和验证；历史密钥禁止与启动密钥相同。主页面可将本机加入信任名单，下次仍显示身份界面，但无需填写启动密钥即可进入；历史记录始终要求独立验证。
- 今日记录 / 本年总结切换、曜日默认标签、约 0.85 秒防抖自动保存及 `Ctrl+S`；当下界面不允许切换到过去日期。
- 中文 / English 即时切换，中文界面采用简练的功能性表述。
- 图片和录音都在填写标签后按光标位置嵌入正文，只显示可点击标签；录音使用标签上方的圆形播放器，图片先显示小预览，再点击查看大图。
- 只读月历、唯一标注 / 跨年标注；标注文字直接显示在对应日期格内。
- 纯 Canvas 计算生成的银河尘埃带、星团、多层恒星、彩色星云与全息地球，不使用背景贴图或地图贴图。
- 1 + 2 + 2 + 7 的纪念星位；正文滚动与天幕手势分离，日记到达底部后需结束当前滚动并再次向下滚动才会显露星空。
- 二次验证后的只读过去查阅；纵向测微式时轨以年为主刻度、实际记录日为三级细分刻度，支持滚动、拖动与键盘选择。
- 独立加密档案支持虚拟目录浏览、筛选、加密导入、临时解密打开和按需提取；文件名、目录结构和文件本体均不写入项目目录。
- 旧 TXT 日记分段导入、带 SHA-256 清单的结构化记录 ZIP 导出。
- Windows 程序文件夹与 `Gobsmacked.exe` 启动器构建配置。

详细范围和阶段状态见 [工程工作清单](docs/WORKLIST.md)，记录格式见 [Gobsmacked Record 规范](docs/FORMAT.md)。

## 开发运行

需要 Node.js 22 或更高版本。

```powershell
npm install
npm test
npm start
```

## 生成 Windows 程序文件夹

```powershell
npm run pack
```

产物直接写入项目根目录。双击 `E:\Gobsmacked\Gobsmacked.exe` 启动；根目录中的 `resources`、`locales`、DLL 与数据文件都是运行所需组件。它们是本地运行产物，不提交到源码仓库。

## 资料保存位置

开发版和安装版默认使用 Electron 的系统用户数据目录。Windows 通常位于：

```text
%APPDATA%\Gobsmacked\vault
```

真实位置由 Electron 在运行时确定。它只保存结构化记录、记录内图片和录音、日期标注及天幕事件。

大文件与程序、结构化记录分开保存。默认密文仓库位于程序目录的同级路径：

```text
E:\Gobsmacked.Archive\
  archive.info
  manifest.gobseal
  objects\<加密对象>.gse
```

清单和对象采用 AES-256-GCM 加密，密文目录不暴露原文件名。受保护的本机密钥状态位于 Electron 用户数据目录，不写入项目。程序只在“历史记录 → 资料”通过二次验证后解锁清单；打开文件时写入会话临时目录，退出内层或关闭程序时清理。

## 备份与安全边界

- “导出记录”只读取结构化资料库并生成 ZIP，不删除源文件，也不会把数十 GB 的大文件仓库隐式塞入压缩包。
- “提取”只解密当前选中的资料或目录到指定位置，保留密文原件；导入同名文件会生成不冲突的新名称并立即加密。
- ZIP 根目录的 `checksums.json` 保存每个资料文件的 SHA-256，可用于迁移后验证。
- 当前档案使用 AES-256-GCM 并由 Windows 当前用户保护密钥状态；这可防止只取得项目目录或密文目录的人直接读取，但不能防御已经控制当前 Windows 账户的恶意程序。仍建议启用 BitLocker。
- 在正式迁移前，建议先保留原资料库，再检查导出 ZIP 可正常解压且校验清单存在。
- 地点窗口仅保留文字输入、保存和定位。直接保存完全离线；主动定位时才会将地点文字发送给 OpenStreetMap Nominatim，结果保存在本地缓存。

## 源码仓库边界

Git 仓库只保存 `src/`、`test/`、通用 `scripts/`、工程文档和依赖清单。`.gob` 记录、媒体、密文对象、密钥、安全配置、导入报告、运行时文件和个人文档均被忽略。提交前应运行 `git status --ignored`，确认没有私人资料进入暂存区。
